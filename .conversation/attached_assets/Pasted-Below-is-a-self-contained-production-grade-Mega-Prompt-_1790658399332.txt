10. Database Schema (Production SQL for PostgreSQL)
Create a Supabase migration containing production-ready SQL.

Use UUID primary keys.

Enable UUID generation using an appropriate PostgreSQL/Supabase-supported extension or UUID generation function available in the target environment.

Profiles
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  full_name text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

Advisory Requests
create table public.advisory_requests (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,

  crop text not null,
  crop_variety text,

  location text not null,

  farm_size numeric(14,4) not null check (farm_size > 0),
  farm_size_unit text not null
    check (farm_size_unit in ('acre', 'hectare', 'square_meter', 'square_foot')),

  soil_type text not null,
  soil_ph numeric(4,2),
  soil_fertility text,
  previous_crop text,

  irrigation_availability text not null,
  water_source text,

  growth_stage text not null,
  planting_date date,
  season text,

  average_temperature numeric(6,2),
  rainfall_information text,
  current_weather text,

  pest_symptoms text,
  disease_symptoms text,
  plant_observations text,
  fertilizer_applied text,

  primary_concern text not null,
  additional_notes text,

  status text not null default 'pending'
    check (status in ('pending', 'generating', 'completed', 'failed')),

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

Advisories
create table public.advisories (
  id uuid primary key default gen_random_uuid(),
  request_id uuid not null unique
    references public.advisory_requests(id) on delete cascade,

  user_id uuid not null references auth.users(id) on delete cascade,

  summary text not null,

  crop_suitability jsonb not null default '[]'::jsonb,
  key_observations jsonb not null default '[]'::jsonb,
  immediate_priorities jsonb not null default '[]'::jsonb,
  soil_recommendations jsonb not null default '[]'::jsonb,
  irrigation_recommendations jsonb not null default '[]'::jsonb,
  nutrition_recommendations jsonb not null default '[]'::jsonb,
  pest_disease_recommendations jsonb not null default '[]'::jsonb,
  growth_stage_recommendations jsonb not null default '[]'::jsonb,
  preventive_practices jsonb not null default '[]'::jsonb,
  monitoring_checklist jsonb not null default '[]'::jsonb,
  harvest_considerations jsonb not null default '[]'::jsonb,
  risks_and_warnings jsonb not null default '[]'::jsonb,
  information_gaps jsonb not null default '[]'::jsonb,

  confidence_level text not null
    check (confidence_level in ('low', 'moderate', 'high')),

  confidence_explanation text not null,

  generated_by_model text,
  generation_duration_ms integer,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()

You are an AI-powered agricultural crop advisory assistant.

18. Security Requirements
Security is a mandatory production requirement.

Secrets
Never expose:

Gemini API key.

Supabase service-role key.

Database passwords.

Private signing secrets.

Never commit .env files containing secrets.

Create .env.example containing variable names only.

Authentication
Use Supabase Auth.

Verify authentication server-side.

Never trust a user ID supplied by the client.

The authenticated identity must come from the validated Supabase access token/session.

Authorization
Every resource request must verify ownership.

Do not rely exclusively on frontend route guards.

Database
Use parameterized Supabase/PostgreSQL operations.

Never construct raw SQL using untrusted string interpolation.

Keep RLS enabled.

Input Validation
Validate:

Body.

Params.

Query parameters.

AI responses.

Environment variables.

Reject unexpected or malformed input.

XSS
Do not render AI-generated content as raw HTML.

Render generated content as text.

Avoid unsafe HTML injection.

Prompt Injection
Treat all user-entered text as untrusted data.

The user's crop notes, symptoms, and additional notes must never override system-level AI rules.

Explicitly instruct the model that user-provided text is data to analyze, not instructions controlling the AI system.

Abuse Prevention
Implement:

Rate limiting.

Request body limits.

AI generation throttling.

Reasonable text-length limits.

Timeout handling.

Retry limits.

Error Handling
Use centralized Express error handling.

Production errors must not reveal:

Stack traces.

API keys.

SQL queries.

Internal filesystem paths.

Provider credentials.

Internal prompts.

Logging
Log:

Request correlation ID.

User ID where appropriate and privacy-safe.

Endpoint.

Duration.

Status.

AI generation success/failure.

Validation failures.

Do not log:

Passwords.

Access tokens.

API keys.

Sensitive user content unnecessarily.

CORS
Configure CORS using an explicit allowed-origin environment variable.

Do not use unrestricted * in production when credentials/authentication are involved.

HTTP Security
Use appropriate Express security middleware such as Helmet where compatible.

Rate Limiting
Protect especially:

POST /api/v1/advisories
POST /api/v1/advisories/:id/retry
POST /api/v1/auth-related endpoints where applicable
